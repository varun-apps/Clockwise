04

Human-in-the-loop & durable execution

The non-obvious part. The review pause can last minutes, so the request can't be held open. The graph runs to the interrupt, checkpoints, and returns — a later call resumes from that exact point.

CLIENT (React)
SERVER (FastAPI + graph)

2 · runGuardrail → supervisor → specialists → itinerary, until interrupt()
3 · checkpointFull TravelState written to Postgres, keyed by thread_id

4 · awaiting reviewReceives the draft itinerary + thread_id; renders Approve / Request changes
connection closed · no worker held · resume any time
→
5 · decisionPOST /resume · {approve | changes + edits}
6 · resumeRehydrate from checkpoint; continue from the interrupt — approve → final, changes → loop back
←
7 · planFinal response streamed in
Open decision: whether steps 2 & 6 run inline or on a background worker, and how progress streams meanwhile. The checkpoint makes either safe — this is the execution-model pass still to be designed.
